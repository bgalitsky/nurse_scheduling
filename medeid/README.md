# medeid 2.2.0 — обезличивание медицинских документов (PDF/DOCX → TXT)

> **Конфиденциально.** Описание способов обезличивания — сведения, доступ к которым закрыт для третьих лиц (прил. 1, п. 2, пп. 2). Репозиторий должен быть закрытым, см. **SECURITY.md**.

## Четыре хранилища

| Хранилище | Где по умолчанию | Кто имеет доступ |
|---|---|---|
| Правила и настройки: `config.yaml`, `roles.yaml`, `llm_prompt.yaml`, `dicts/` | Windows: `C:\ProgramData\medeid\settings`, иначе `~/medeid_settings` (или `MEDEID_SETTINGS`) | только отдел ИБ (операторам — чтение) |
| Исходные документы (+ `.medeid/registry.sqlite`: DOC-номер ↔ файл) | `~/medeid_data/source` | оператор |
| Результаты: `<партия>/DOC-000001.txt`, `manifest.json` | `~/medeid_data/results` | оператор, исследователь |
| Ключи и кэш модели (ПДн) / журнал (без ПДн) | `~/medeid_secure/`, `~/medeid_journal/` — задаются в `config.yaml` | администратор ключей / администратор |

Хранилища не могут лежать друг в друге или внутри папки программы: иначе программа не запустится. Все файлы и папки, которые создаёт программа, называются только латиницей.

## Первый запуск

```powershell
cd <папка программы>                      # где лежат run_app.py и папка medeid
pip install -r requirements.txt
python -m medeid settings init            # создать папку настроек из templates/ (делает ИБ)
python -m medeid check-model              # если используется языковая модель (INSTALL_LLM.md)
python -m medeid rules -o deid_rules.docx # правила обработки → юристу, к приказу
python run_app.py                         # окно (или python -m medeid app)
```

После подписания приказа отдел ИБ вписывает его в `config.yaml`:
```yaml
утверждение:
  редакция: R-D2002DB124        # из выгрузки правил
  приказ_номер: "77-о"
  приказ_дата: "18.11.2026"
```
Если после этого изменить правила в `config.yaml` (режимы, типы документов, сквозной код, сдвиг дат), обработка будет запрещена, пока новая редакция не утверждена. Каждая партия записывается в журнал с редакцией правил и отметкой, утверждены ли они.

## Командная строка

```bash
python -m medeid settings init|where [--to ПАПКА]
python -m medeid rules  [-o deid_rules.docx|.txt]               # правила для локального акта
python -m medeid run    -i source/ -o results/                   # → results/<партия>/
python -m medeid verify -i source/ -b 2026-11-19-001 [-o results/]   # повторяемость + целостность файлов
python -m medeid check-model
python -m medeid reveal --code ПАЦИЕНТ_0042 --reason "Приказ № …"
```
Ключ `-c ПУТЬ/config.yaml` задаёт другую папку настроек (рядом с этим файлом должны лежать `dicts/` и `llm_prompt.yaml`).

## Окно приложения

Роль определяется по учётной записи ОС и файлу `roles.yaml` в папке настроек.

- **Оператор**:
  - вкладка «Партия»: папки, основание партии, переключатель языковой модели (вкл/выкл, «модель + правила» / «только модель»), запуск;
  - вкладка «Правила»: просмотр действующих правил; изменить их в окне нельзя;
  - вкладка «Партии»: ручная проверка, повторяемость, удаление исходников или результатов;
  - вкладка «Отзыв согласия».
- **Администратор**:
  - журнал партий (с редакцией правил);
  - события и выдача, выгрузка CSV для акта об уничтожении;
  - **Правила для приказа**: просмотр и сохранение в DOCX или TXT;
  - ключи: без ФИО, раскрытие с основанием.

  К документам администратор доступа не имеет.

Разграничение в окне не заменяет прав доступа NTFS на хранилища (см. GAPS.md, SECURITY.md).

## Что получает исследователь

Папка `results/<партия>/`: тексты `DOC-xxxxxx.txt` и `manifest.json`, в котором только номера документов и контрольные суммы. Сведений о модели, словарях, режимах и замечаниях проверки там нет: они хранятся в журнале. Документы с замечаниями лежат в `_review/` и до ручной проверки не выдаются.

## Режимы (config.yaml → категории_и_режимы)

| Категория | Режимы |
|---|---|
| фио_пациента | `замена_меткой` → `[ФИО_ПАЦИЕНТА]`, `удаление`, `сквозной_код` → `ПАЦИЕНТ_0042` |
| фио_врачей | `специальность` → `[ВРАЧ-КАРДИОЛОГ]`, `[ЗАВ_ОТДЕЛЕНИЕМ]`…, `замена_меткой`, `удаление` |
| фио_родственников / фио_прочие | `замена_меткой`, `удаление` |
| номера_документов, место_работы | `замена_меткой` (`[num]`, `[МЕСТО_РАБОТЫ]`), `удаление` |
| адрес | `обобщение_до_города`, `замена_меткой`, `удаление` |
| телефон, email, снилс_полис_паспорт (+ИНН), номер_истории | `удаление` → `[УДАЛЕНО: тип]`, `замена_меткой` |
| даты | `оставить`, `только_год`, `квартал`, `сдвиг`, `замена_меткой`, `удаление` |
| возраст | `как_есть`, `возрастная_группа`; старше 89 → `возраст_старше_89` всегда |

## Как ищутся сведения (для разработчиков и ИБ)

1. Поля шапки дают пациента документа. Падежные формы его фамилии, имени и отчества ищутся по всему тексту; найденная фамилия всегда дополняется до полного ФИО.
2. Правила для ФИО, адресов, документов, телефонов, дат и возраста. Словари берутся из папки настроек.
3. Локальная языковая модель (инструкция — `llm_prompt.yaml` в папке настроек) находит фрагменты по смыслу. Каждый фрагмент проверяется дословным поиском.
4. Контроль: текст вне замен не изменился, дозы и анализы совпадают; повторный поиск по результату. Если что-то найдено, документ уходит в `_review/`.

## Повторяемость

Та же конфигурация (правила, версии, словари, инструкция, модель) на тех же файлах даёт побайтно тот же результат. `verify` повторяет партию по конфигурации из журнала, сверяет результат с контрольными суммами из журнала и проверяет, не изменены ли сохранённые файлы. Исключение: `сдвиг` дат с удалением величины сдвига.

## Изменения в 2.2.0

- **Только латиница в именах** файлов и папок: словари `first_names.txt`, `cities.txt`, `eponyms.txt`; папки `source`, `results`, `_review`; выгрузки `deletion_log.csv`, `event_log.csv`, `deid_rules_<редакция>_<дата>.docx`.
- **Выгрузка правил для локального акта** (прил. 1, п. 2, пп. 3 и 6): DOCX или TXT, команда `rules` и вкладка администратора. У правил есть редакция (`R-…`), которая записывается в журнал каждой партии. Изменить правила после утверждения без нового приказа нельзя.
- **Отдельная папка настроек** только для ИБ: `config.yaml`, словари, инструкция для модели (убрана из кода), роли. Личные папки пользователя хранятся в `~/.medeid/app_prefs.yaml`.
- **Не раскрывать способы обезличивания** (прил. 1, п. 2, пп. 2): в папке результатов нет сведений о методах; оператор не меняет правила; `.gitignore` и SECURITY.md для закрытого репозитория.
- `verify` работает по журналу (`-b <партия>`) и проверяет целостность сохранённых файлов.

История 1.x–2.1: исправления ФИО (2.1.1), окно приложения, партии, реестр, отзыв согласия (2.1), языковая модель (2.0), DOCX и колонтитулы (1.4), специальность врача и `[num]` (1.5).
