# medeid 2.1.0 — обезличивание медицинских документов (PDF/DOCX → TXT)

## Приложение (окно)

```powershell
cd <папка medeid>            # та, где лежат config.example.yaml и папка medeid
python -m medeid app
```
При первом запуске создаются `roles.yaml` (роли по учётным записям ОС) и папки по умолчанию:

| Хранилище | Папка по умолчанию | Кто видит |
|---|---|---|
| Исходные документы | `~/medeid_data/исходники` | оператор |
| Обезличенные результаты | `~/medeid_data/результаты/<партия>/DOC-000001.txt` | оператор, исследователь |
| Ключи и кэш модели (ПДн) | `~/medeid_secure/` | администратор ключей |
| Журнал (без ПДн) | `~/medeid_journal/journal.sqlite` | администратор, проверяющий |
| Правила и настройки | папка программы (`config.yaml`, `dicts/`, `roles.yaml`, `app_settings.yaml`) | отдел ИБ |

Пути меняются в `app_settings.yaml`. Оператор может выбрать другие папки исходников и результатов прямо в окне и сохранить их как папки по умолчанию.

**Оператор**:
- вкладка «Партия»: папки, основание, типы документов, **переключатель языковой модели** (вкл/выкл, «модель + правила» / «только модель», проверка модели), сквозной код, запуск;
- вкладка «Режимы»: режим для каждой категории;
- вкладка «Партии»: ручная проверка, повторяемость, удаление исходников или результатов партии;
- вкладка «Отзыв согласия».

**Администратор**: журнал партий (документы только по DOC-номерам, хеши, версии, конфигурация партии), события (выдача, копирование, удаление, выгрузка CSV для акта), ключи (коды без ФИО; раскрытие — с основанием и записью в журнал). К папкам с документами администратор доступа не имеет.

Разграничение в окне не заменяет прав доступа: на каждое хранилище выставьте права NTFS (см. GAPS.md).

Python для Windows с python.org уже включает tkinter (пункт «tcl/tk and IDLE» при установке).

Соответствие требованиям «Инструкции для разработчика» и что ещё не сделано — в **GAPS.md**.

## Изменения в 2.1.0

- Окно приложения (tkinter) с ролями «оператор» и «администратор».
- Партии с номерами вида `2026-11-11-001`. Результаты лежат в `<результаты>/<партия>/`, имя файла — только внутренний номер `DOC-000187.txt`.
- Реестр хранилища исходников: связь «DOC-номер ↔ исходный файл» и отзыв согласия. Журнал событий: регистрация, выдача, копирование, удаление, ручная проверка, раскрытие ключа. Выгрузка CSV для акта об уничтожении.
- Режим «удаление» теперь ставит `[УДАЛЕНО: тип]` («вырезается и замещается типом данных»).
- Автоматическая проверка: текст вне найденных фрагментов не изменён, дозы, единицы и анализы совпадают.
- Поиск устойчив к латинице внутри русских слов («Мaзypенко») и к ё/е.
- Новые категории: ИНН, место работы или учёбы.
- Изображения не переносятся, на их месте метка `[ИЗОБРАЖЕНИЕ УДАЛЕНО]`. Сверяется число страниц, страницы-сканы и «иероглифы» отправляются на ручную проверку. Повреждённые и запароленные файлы отклоняются с записью в журнал.
- Новая версия словарей `2026-11-11`: эпонимы из инструкции (синдром Жильбера и др.).
- Проверка, что хранилища не вложены друг в друга.

Берёт выписные эпикризы, протоколы консилиумов, осмотры врачей и результаты обследований в PDF или DOCX, убирает всё, по чему можно узнать пациента, и сохраняет результат в `.txt`.

## Запуск

```bash
pip install -r requirements.txt
python -m medeid run    -c config.yaml -i исходники/ -o результаты/          # → результаты/<партия>/
python -m medeid verify -c config.yaml -i исходники/ -o результаты/<партия>/   # проверка повторяемости
python -m medeid check-model -c config.yaml                           # проверка локальной модели
python -m medeid reveal --keystore /secure/keys.sqlite --code ПАЦИЕНТ_0042 \
                        --user petrov.pp --reason "Приказ № 142-о, запрос ..."
```

Конфигурация — `config.example.yaml`. Без заполненного основания (приказ, дата, цель, отделение) инструмент не запустится. Если версия инструмента, модели или словарей расходится с указанной в конфигурации, запуск тоже не начнётся.

## Изменения в 2.0.0

- Фрагменты для замены находит **локальная языковая модель** (Ollama или llama.cpp) вместе с правилами (`извлечение: модель+правила`) или без них (`модель`). Установка — в **INSTALL_LLM.md**.
- Модель только указывает фрагменты, а заменяет их код. Фрагмент, которого нет в тексте дословно, отбрасывается.
- Сервер модели должен быть на localhost или во внутренней сети. Перед запуском сверяется дайджест модели. Ответы модели кэшируются, поэтому повторный запуск даёт тот же результат.
- Новая команда `python -m medeid check-model -c config.yaml` проверяет установку модели.
- Параметр `версия_модели` удалён: вместо него используются `извлечение` и секция `модель`.

## Изменения в 1.5.0

- Новый режим `фио_врачей: специальность`. Вместо ФИО ставится специальность или должность врача. Она берётся из строки: «(кардиолог)», «врач-невролог», «Зав. отделением», «Председатель консилиума». Если в строке ничего нет, специальность берётся из заголовка («Осмотр врача-химиотерапевта» → `[ВРАЧ-ХИМИОТЕРАПЕВТ]`). Подпись «/Сидоров/» получает ту же метку, что этот врач в шапке.
- Строка «Врач: …» всегда относится к врачу, даже если ФИО совпадает с ФИО пациента.
- Новая категория `номера_документов` → `[num]`. Сюда входят всё после «№», коды гистологии и ИГХ (2266K25000807-1, 20-6124) и целые числа от 6 цифр. Дозы, результаты анализов и размеры не затрагиваются.

## Изменения в 1.4.0

- Добавлен ввод DOCX. Колонтитулы читаются обязательно: в выгрузках МИС в них бывают ФИО, дата рождения, полис и адрес.
- Добавлен тип документа `осмотр_врача`.
- Распознаются адреса вида «Люблинская улица, д. 72, к. 3, кв. 187».
- Распознаются новые форматы дат: «12,05.2020», «08.04 2025», «09.2021г», «с 08.23», «09.24-01.25», «05-07.2023», «07.08..23». Невозможные даты («37 сентября 1976») тоже считаются датами.
- «им. А.С. Логинова» распознаётся как название учреждения, а не как ФИО. Склеенные слова («НиколаевичПациент») разделяются.

## Режимы

| Категория | Режимы |
|---|---|
| фио_пациента | `замена_меткой` → `[ФИО_ПАЦИЕНТА]`, `удаление`, `сквозной_код` → `ПАЦИЕНТ_0042` |
| фио_врачей | `специальность` → `[ВРАЧ-КАРДИОЛОГ]`, `[ЗАВ_ОТДЕЛЕНИЕМ]`…, `замена_меткой`, `удаление` |
| фио_родственников / фио_прочие | `замена_меткой`, `удаление` |
| номера_документов | `замена_меткой` → `[num]`, `удаление` |
| адрес | `обобщение_до_города` → «Москва» (только города из словаря, иначе `[НАСЕЛЁННЫЙ_ПУНКТ]`), `замена_меткой`, `удаление` |
| телефон, email, снилс_полис_паспорт, номер_истории | `удаление`, `замена_меткой` |
| даты | `оставить`, `только_год`, `квартал` (IV кв. 2026), `сдвиг`, `замена_меткой`, `удаление` |
| возраст | `как_есть`, `возрастная_группа` (50–59); старше 89 → `возраст_старше_89` всегда, дата рождения таких пациентов → `[90+]` |

**Сдвиг дат.** Все даты одного пациента во всех его документах сдвигаются на одну и ту же случайную величину (не 0, в пределах `диапазон_дней`). Если `после_обработки: удалить`, величина существует только в памяти на время запуска. Если `хранить_в_ключе`, она хранится в БД ключей.

**Сквозной код.** Если `сквозной_код_пациента: да`, ключ «код ↔ пациент» создаётся обязательно. Он хранится в `хранилище_ключей`: это отдельная SQLite-БД с правами 0600. Инструмент откажется работать, если она лежит внутри каталога входных файлов или результатов. Пациент определяется по фамилии, инициалам и дате рождения. Каждое создание кода и каждое раскрытие (`reveal`) записываются в `access_log` этой БД.

## Как ищутся сведения

1. Поля шапки (`ФИО пациента:`, `Пациент:`, `Дата рождения:`) дают пациента документа.
2. Все падежные формы фамилии пациента ищутся по всему тексту (кроме эпонимов: «болезнь Паркинсона»).
3. ФИО по шаблонам: Фамилия И.О., И.О. Фамилия, Фамилия Имя Отчество, Имя Отчество, подпись `/Сидоров/`. Роль (пациент, врач, родственник) определяется по контексту строки. Если фамилия как у пациента, а инициалы другие, это родственник.
4. Регулярные выражения для адресов, телефонов, email, СНИЛС, полиса, паспорта, номера истории болезни, дат и возраста.
5. Локальная языковая модель (секция `модель`, см. INSTALL_LLM.md) находит фрагменты по смыслу. Каждый найденный фрагмент проверяется дословным поиском в тексте.
6. **Контроль остатков.** Обработанный текст проверяется повторно. Если что-то найдено, файл попадает в `результат/_на_проверку/` со статусом `требует_проверки`.

## Повторяемость

- Порядок обработки задаётся хешами содержимого PDF, а не именами файлов. Дубликаты обрабатываются один раз.
- В выходном тексте нет дат обработки и прочих меток запуска. Всё служебное записывается в `manifest.json` и журнал.
- *Отпечаток запуска* = sha256 (параметры конфигурации + версии + хеш словарей + хеш модели + хеши входных файлов). Поля `запустил` и `основание` на результат не влияют и в отпечаток не входят.
- `verify` повторяет обработку во временном каталоге и побайтно сравнивает результат. Исключение: `сдвиг` + `удалить`. Там несовпадение ожидаемо, потому что величина сдвига удалена.

## Что где лежит

| Файл | Содержит ПДн | Назначение |
|---|---|---|
| `результат/*.txt` | нет | обезличенные тексты; имя файла = `[код_]тип_хеш.txt`, исходное имя не используется |
| `результат/manifest.json` | нет | версии, отпечаток, основание, счётчики замен по категориям (без значений) |
| `журнал` (SQLite) | нет | история запусков и файлов |
| `хранилище_ключей` (SQLite) | **да** | код ↔ ФИО + дата рождения, сдвиги дат, журнал доступа |

## Ограничения

- Сканы без текстового слоя не обрабатываются (статус `ошибка_извлечения`). Сначала их нужно распознать, например `ocrmypdf -l rus`.
- Правила рассчитаны на типовую структуру документов. Свободный текст (анамнез со слов, необычные прозвища, редкие названия населённых пунктов) нужно проверять выборочно, особенно файлы из `_на_проверку`.
- Название ЛПУ (например, «ГКБ № 1 г. Москвы») не удаляется.
- БД ключей хранится без шифрования. Её нужно размещать на защищённом томе или шифровать на уровне ФС.
