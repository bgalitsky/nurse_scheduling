# Конфиденциальность способов обезличивания (прил. 1, п. 2, пп. 2)

Больница обязана закрыть третьим лицам доступ к локальным актам и к сведениям о методах и программах обезличивания. Если словари, шаблоны и инструкция для модели открыты, можно заранее понять, что программа пропустит, например имя, которого нет в словаре.

## Что сделано в программе (medeid 2.2.0)

| Что | Где теперь |
|---|---|
| Утверждённые правила, пути хранилищ, дайджест модели (`config.yaml`) | **папка настроек** больницы |
| Словари (`dicts/<версия>/first_names.txt, cities.txt, eponyms.txt`) | **папка настроек** |
| Инструкция для языковой модели (`llm_prompt.yaml`) | **папка настроек** (из кода программы удалена) |
| Роли (`roles.yaml`) | **папка настроек** |
| Номер приказа, отделение, утверждённая редакция правил | только **папка настроек** и **журнал** |

Папка настроек: `C:\ProgramData\medeid\settings` (Windows), `~/medeid_settings` или путь из переменной `MEDEID_SETTINGS`. Она создаётся командой `python -m medeid settings init`. Доступ к ней должен быть только у отдела ИБ (права NTFS), операторам — чтение.

- Программа отказывается работать, если папка настроек лежит внутри папки программы, исходников или результатов.
- В папку результатов (её получают исследователи) кладутся только тексты и `manifest.json` с номерами документов и контрольными суммами. Сведения о модели, словарях, режимах и замечаниях проверки хранятся только в журнале.
- Оператор не может менять правила в окне программы: только просмотр. Изменить их может только отдел ИБ в `config.yaml`. После изменения обработка запрещена, пока новая редакция не утверждена приказом (если в `config.yaml` есть раздел `утверждение`).
- Папка `templates/` в программе содержит только **обобщённые шаблоны**. Дополнения конкретной больницы (свои словари, правки инструкции) вносятся в её папку настроек и в репозиторий не попадают (см. `.gitignore`).

## Перенос репозитория в закрытый (делает владелец репозитория)

1. **Сделать репозиторий закрытым.** На GitHub: Settings → General → Danger Zone → Change repository visibility → Private. Или командой:
   ```bash
   gh repo edit <владелец>/<репозиторий> --visibility private --accept-visibility-change-consequences
   ```
2. **Проверить, кто имеет доступ:** Settings → Collaborators and teams. Оставить только разработчиков.
3. **Проверить форки.** Публичные копии, сделанные до закрытия, остаются у их владельцев и закрытием не убираются. Посмотрите Insights → Forks. Если такие копии есть, считайте их содержимое раскрытым.
4. **Проверить историю коммитов** на настройки конкретной больницы: `config.yaml` с номером приказа и отделением, `roles.yaml`, журналы `*.sqlite`, документы. Если они попадали в историю, удалите их из всей истории (`git filter-repo`) и сделайте принудительную отправку. Скопированное кем-то до этого всё равно остаётся раскрытым.
5. **Считать раскрытым всё, что уже было открыто**: словари и инструкцию для модели из публичной версии. Для больницы стоит дополнить словари и изменить инструкцию **в своей папке настроек**. Тогда действующие правила поиска будут отличаться от того, что видели посторонние.
6. Не публиковать журнал, выгрузку правил (`deid_rules_*.docx`) и папку настроек ни в каком виде. Правила передаются юристу как конфиденциальный документ.

## Чего программа сделать не может

- Выставить права доступа к папкам (NTFS / группы AD) — это делает отдел ИБ.
- Закрыть репозиторий, отозвать форки и чужие копии — это делает владелец репозитория (см. выше).
- Помешать сотруднику с доступом к папке настроек скопировать её — это вопрос регламента и журналирования доступа на уровне ОС.
